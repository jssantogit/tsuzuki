## Triangulation and narrow fix in this branch

The public MangaFire title page for `52020` credits **KUI Ryoko**, while independent catalogs credit **Ryouko Kui**, **Ryōko Kui**, and **Ryoko Kui**. The existing Host `ProviderWorkSourcePortfolio.normalizeCreator` sorted name tokens but compared accented and long-vowel romanized spellings literally, which can yield `AUTHOR_CONFLICT` for the full same name. This is a plausible *mechanism* for Dungeon Meshi; do not claim the private cache's exact spelling is proven.

A RED test uses the **actual observed HID** with the known source author and independently catalog-attested spellings. It asserts only a provisional eligible source association on a full-name match, **never canonical promotion, Reader grant, automatic preferred edition selection**, nor surname-only evidence. Actual strict `CollectProviderReadingEvidence.normalizedCreator` remains unchanged. The code change folds macrons and narrowly attested long-`you` syllable romanizations only for multi-token names **inside the provisional portfolio**; other whole names must still mismatch. It is not evidence that a new A54 capture will definitively resolve Dungeon Meshi.

[RED Host CI #43763374364](https://github.com/jssantogit/tsuzuki/actions/runs/43763374364) had 1 failure in 1210 Domain tests, exactly the new Dungeon Meshi test. GREEN Host CI and outcome should be verified before merge.
